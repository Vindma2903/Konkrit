# Дельта: выбор дома и привязка квартиры

Экраны макета: «Вход: выбор дома», «Вход: привязка квартиры».

## ADDED Requirements

### Requirement: Поиск дома
Экран «Ваш дом» MUST содержать поле поиска «Город, улица, дом», счётчик «Найдено: N»
и список домов. Карточка дома: иконка, название (ЖК или дом), адрес, «УК [название]».

#### Scenario: Поиск
- **WHEN** пользователь печатает запрос
- **THEN** через 400 мс после паузы вызван `searchHouses({ query })`, список заменён результатом, счётчик обновлён

#### Scenario: Пустой результат
- **WHEN** по запросу ничего не найдено
- **THEN** показано «Ничего не найдено. Уточните адрес или выберите «Моего дома нет в списке»»

#### Scenario: Ошибка загрузки
- **WHEN** `searchHouses` завершился ошибкой
- **THEN** вместо списка сообщение об ошибке и кнопка «Повторить»

### Requirement: Выбор дома
Карточки MUST работать как одиночный выбор: выбранная — рамка `#CC3D3D` 2 px и красная
галочка в круге, остальные — серое пустое кольцо. Кнопка «Продолжить» MUST быть неактивна, пока дом не выбран.

#### Scenario: Выбор
- **WHEN** пользователь нажимает карточку
- **THEN** она выбрана, выбор другой карточки снимает предыдущий
- **WHEN** нажата «Продолжить»
- **THEN** дом сохранён в состоянии онбординга, открыт «Привязка квартиры»

### Requirement: Дома нет в списке
Ссылка «Моего дома нет в списке» MUST присутствовать на экране. Сценарий после нажатия
не входит в это изменение.

#### Scenario: Нажатие
- **WHEN** пользователь нажимает ссылку
- **THEN** показан информационный лист «Эта возможность скоро появится» (заглушка)

### Requirement: Форма привязки квартиры
Экран «Привязка квартиры» MUST показывать выбранный дом (адрес и УК) и поля «Квартира»,
«Лицевой счёт», выбор роли («Собственник» / «Жилец») и способ подтверждения
(«По коду из квитанции» / «По документу»). Поля идут друг под другом.

#### Scenario: Значения по умолчанию
- **WHEN** экран открыт
- **THEN** роль «Собственник», способ «По коду из квитанции»

#### Scenario: Валидация
- **WHEN** поле «Квартира» пусто или не число
- **THEN** кнопка «Отправить на подтверждение» неактивна
- **WHEN** выбран способ «По коду из квитанции» и «Лицевой счёт» пуст
- **THEN** кнопка неактивна, под полем после потери фокуса ошибка «Введите номер лицевого счёта»
- **WHEN** выбран способ «По документу»
- **THEN** поле «Лицевой счёт» остаётся необязательным

#### Scenario: Способ «По документу»
- **WHEN** выбрано «По документу» и нажата отправка
- **THEN** отправляется только выбор способа (загрузка документа не входит в это изменение, экран загрузки будет отдельным изменением)

### Requirement: Отправка на подтверждение
По нажатию MUST вызываться `ApiClient.submitResidency`. Статус привязки — «ожидает
подтверждения УК».

#### Scenario: Успех
- **WHEN** `submitResidency` вернул `pending`
- **THEN** показана заглушка «Заявка на привязку отправлена. УК проверит данные», с кнопкой «На главную» (заглушка главной)

#### Scenario: Ошибка
- **WHEN** `submitResidency` завершился ошибкой (в т. ч. сеть)
- **THEN** введённые данные сохранены, показано сообщение под кнопкой, кнопка снова активна

### Requirement: Возврат назад
Кнопка «Назад» MUST возвращать на предыдущий экран, не теряя введённое.

#### Scenario: Назад с привязки
- **WHEN** пользователь вернулся на «Ваш дом» и снова нажал «Продолжить»
- **THEN** ранее введённые квартира, счёт и роль сохранены, если дом тот же; при смене дома поля очищены
