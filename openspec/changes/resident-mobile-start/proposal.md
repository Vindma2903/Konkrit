# Старт мобильного приложения жителя: вход, привязка квартиры, новая заявка

## Зачем

Начинаем разработку по дизайну «Конкрит — дизайн», страница «Жилец». Нужен первый
сквозной путь жителя в мобильном приложении: войти → выбрать дом → привязать квартиру →
создать заявку. Это вход в MVP-ядро из ТЗ (модуль заявок, приоритет P0).

## Что меняется

- Создаётся мобильное приложение `mobile/` (React Native + TypeScript) с темой «Коралл»,
  базовыми UI-компонентами и навигацией.
- Экраны входа и онбординга жителя (6 экранов): телефон, почта, код из SMS, код из письма,
  выбор дома, привязка квартиры.
- Экран «Новая заявка» в состояниях S1 (пустая), S2 (ввод и подсказка категории),
  S3 (заполнена), S4 (ошибки валидации).
- Слой данных за интерфейсом `ApiClient` с мок-реализацией: бэкенда на Go ещё нет,
  контракт фиксируем сразу в `api/openapi.yaml`, чтобы потом подключить реальный клиент
  без правки экранов.

## Что НЕ входит

Экраны, которых нет в списке запроса, остаются отдельными изменениями:
выбор адреса (S5), вложения (S6, S7a–S7f), лист выбора категории (S12), отправка,
успех и ошибка отправки (S8–S11), главная жителя, список и карточка заявок,
«Моего дома нет в списке», загрузка документа для подтверждения, настройка уведомлений.

## Допущения (проверьте — от них зависит объём)

1. **Expo (managed workflow)** с `expo-router`, а не «голый» React Native. Причина: быстрее
   старт, один инструментарий сборки для iOS и Android. Нативные модули (камера, SIP
   домофона) добавим через development build позже.
2. **Бэкенда нет → мок.** Все вызовы идут через `ApiClient`; в этом изменении работает
   только `mockApi`. Реального HTTP-клиента здесь нет.
3. **Экран «Новая заявка» работает без S5/S6/S12.** Категорию выбираем кнопкой
   «Выбрать» из подсказки (S2) или, если подсказки нет, она остаётся пустой и S4 показывает
   ошибку. Поля «Категория», «Адрес» и «Вложения» рисуются как в макете, но нажатие
   на них пока ничего не открывает. Это значит, что **без S12 заявку с ручным выбором
   категории создать нельзя** — если нужно иначе, добавим S12 в этот объём (около +1 экрана).
4. **Правило кнопки «Отправить заявку».** В S1 она неактивна (серая), пока форма пуста.
   Как только появился ввод — активна; нажатие с ошибками показывает S4. Отправка
   (S8–S11) не входит: после успешной валидации кнопка вызывает `ApiClient.createRequest`
   и показывает временную заглушку «Заявка отправлена».
5. **Состояния вне макетов** (неверный код, истёк таймер, ошибка сети) оформляем теми же
   стилями, что ошибки в S4 (красный #B3261E, иконка-треугольник), отдельных макетов нет.
6. **Репозиторий не под git.** В задачах — `git init`, ветка `main`, рабочая ветка
   `feature/resident-mobile-start`. Push и PR — только по вашей команде.

## Существующие данные

Базы данных и миграций в этом изменении нет: бэкенд не затрагивается, только
описывается контракт (`api/openapi.yaml`). Вопроса «что с данными в базе» нет; при
реализации бэкенда он будет решаться его собственной спекой.
