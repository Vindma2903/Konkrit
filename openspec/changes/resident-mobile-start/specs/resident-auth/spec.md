# Дельта: вход жителя

Экраны макета: «Вход: телефон», «Вход: почта», «Вход: код из SMS», «Вход: код из письма».

## ADDED Requirements

### Requirement: Выбор способа входа
Экран входа MUST содержать переключатель «Телефон / Почта». «Телефон» и «Почта» — один
экран с двумя режимами. Заголовок и описание одинаковы, поле и подсказка под ним зависят
от режима.

#### Scenario: Телефон
- **WHEN** выбран режим «Телефон»
- **THEN** поле «Номер телефона», маска `+7 (000) 000-00-00`, клавиатура телефонная,
  подсказка «Код придёт в SMS.»

#### Scenario: Почта
- **WHEN** выбран режим «Почта»
- **THEN** поле «Электронная почта», почтовая клавиатура,
  подсказка «Код придёт в письме. Проверьте папку «Спам», если не нашли.»

#### Scenario: Смена режима сохраняет ввод
- **WHEN** пользователь вводит телефон, переключается на «Почта» и обратно
- **THEN** введённый телефон не потерян

### Requirement: Запрос кода
Кнопка «Получить код» MUST быть неактивна, пока значение не прошло проверку формата
(телефон РФ: 10 цифр после +7; почта — по `zod.email()`). По нажатию вызывается
`ApiClient.requestCode`, и открывается экран кода.

#### Scenario: Корректный телефон
- **WHEN** введено 10 цифр и нажата «Получить код»
- **THEN** вызван `requestCode({ channel: 'phone', value: '+7XXXXXXXXXX' })`, показан индикатор
  загрузки на кнопке, затем открыт экран «Код из SMS»

#### Scenario: Ошибка сети
- **WHEN** `requestCode` завершился ошибкой
- **THEN** остаёмся на экране входа, под полем показана ошибка «Не удалось отправить код. Проверьте соединение и попробуйте снова», кнопка снова активна

### Requirement: Согласие с условиями
Под кнопкой MUST быть текст согласия. «условиями использования» и
«политикой обработки персональных данных» — ссылки: цвет `#A82E2E`, жирные, подчёркнутые.

#### Scenario: Нажатие ссылки
- **WHEN** пользователь нажимает ссылку
- **THEN** открывается соответствующий документ (адрес берётся из конфигурации; в этом изменении — заглушка с адресом-заменителем)

### Requirement: Ввод кода
Экран кода MUST показывать 6 ячеек, заголовок «Код из SMS» или «Код из письма» по каналу,
введённое значение (телефон/почта) и ссылку «Изменить номер» / «Изменить почту».

#### Scenario: Автопереход
- **WHEN** пользователь вводит цифру в ячейку
- **THEN** фокус переходит в следующую; при удалении в пустой ячейке — в предыдущую

#### Scenario: Вставка кода
- **WHEN** пользователь вставляет или получает из SMS 6 цифр целиком
- **THEN** все ячейки заполняются

#### Scenario: Подтверждение
- **WHEN** введены 6 цифр и нажата «Подтвердить» (или цифры введены полностью)
- **THEN** вызван `verifyCode`; кнопка с индикатором загрузки; при успехе — переход по сценарию ниже

#### Scenario: Неверный код
- **WHEN** `verifyCode` вернул ошибку «неверный код»
- **THEN** ячейки подсвечены красной рамкой `#B3261E`, под ними сообщение «Неверный код. Проверьте и попробуйте ещё раз», ячейки очищаются, фокус в первой

### Requirement: Повторная отправка кода
Под ячейками MUST быть таймер «Отправить код повторно через N с». После окончания таймера
вместо него показывается ссылка «Отправить код ещё раз».

#### Scenario: Таймер
- **WHEN** код отправлен
- **THEN** таймер начинается с `retryAfterSec` из ответа (по умолчанию 60), ссылка неактивна
- **WHEN** таймер дошёл до 0 и пользователь нажал «Отправить код ещё раз»
- **THEN** вызван `requestCode`, таймер стартует заново

### Requirement: Смена канала и ввода
На экране кода MUST быть ссылка «Войти по почте» (для SMS) или «Войти по телефону» (для письма),
а «Изменить номер/почту» и «Назад» возвращают на экран входа.

#### Scenario: Смена канала
- **WHEN** на экране «Код из SMS» нажата «Войти по почте»
- **THEN** открыт экран входа в режиме «Почта»

### Requirement: Маршрутизация после входа
После успешного `verifyCode` приложение MUST сохранить токены в защищённом хранилище и
выбрать дальнейший экран.

#### Scenario: Первый вход
- **WHEN** `hasResidency = false`
- **THEN** открыт «Ваш дом» (онбординг)

#### Scenario: Повторный вход
- **WHEN** `hasResidency = true`
- **THEN** открыта главная жителя (заглушка в этом изменении)

#### Scenario: Запуск с сохранённой сессией
- **WHEN** приложение запущено и в хранилище есть токены
- **THEN** экраны входа пропускаются
