# Дизайн

## Стек и структура
Vue 3 (Composition API, `<script setup>`), Vite, TypeScript, vue-router, Pinia, Vitest + Vue Test Utils, ESLint.
Каталог `web/`:

- `src/api/` — интерфейс `StaffAuthApi`, мок `mockAuthApi.ts`, ошибки `ApiError`; клиент выбирается в одном месте
  (в режиме разработки — мок, в релизной сборке — HTTP-клиент к бэкенду; мок в релизный бандл не попадает).
- `src/features/auth/` — экраны (`LoginView`, `RegisterView`, `PendingView`, `ForgotView`, `SentView`, `ResetView`),
  `AuthLayout` (двухколоночный каркас), `PasswordField`, `PasswordRules`, схемы проверки, хранилище сессии.
- `src/router/` — маршруты и охранники.
- `src/styles/` — токены из макета (цвета, радиусы, типографика).

## Маршруты
| Путь | Экран | Доступ |
|---|---|---|
| `/login` | Вход | только без сессии |
| `/register` | Регистрация | только без сессии |
| `/pending` | Ждёт подтверждения | без сессии |
| `/forgot` | Восстановление пароля | без сессии |
| `/forgot/sent` | Письмо отправлено | без сессии, только после отправки |
| `/reset?token=…` | Новый пароль | без сессии |
| `/` | Заглушка кабинета | только с сессией |

## Контракт (`api/openapi.yaml`)
- `POST /staff/auth/login` `{email, password, remember}` → `{accessToken, user{id,name,role}}` + refresh-кука;
  ошибки: `invalid_credentials`, `pending_approval` (с названием УК и email администратора), `rejected`, `blocked`, `rate_limited`.
- `POST /staff/auth/register` `{name, company, email, phone, password, consent}` → `202 {company, adminEmail}`;
  ошибки: `email_taken`, `validation` (с полями).
- `POST /staff/auth/password/forgot` `{email}` → `202 {retryAfterSec, ttlMin}` — всегда одинаковый ответ, не раскрывает, есть ли такая почта.
- `POST /staff/auth/password/reset` `{token, password}` → `204`; ошибки: `invalid_token` (истёк или использован), `validation`.
- `POST /staff/auth/logout`.

## Решения и допущения
1. **Токены.** Access-токен хранится только в памяти (Pinia), refresh — в `HttpOnly`-куке, ставит бэкенд. В `localStorage`
   токены не пишем. «Запомнить меня» управляет сроком refresh-куки (с флагом — 30 дней, без — до закрытия браузера).
   Мок эмулирует это в `sessionStorage` / `localStorage` только флагом «вошёл», без токенов.
2. **Статус заявки на доступ** приходит ответом входа: `pending_approval` ведёт на «Ждём подтверждения», название УК и
   email администратора берутся из ответа. «Отклонена» и «заблокирован» — сообщение под формой входа (макета нет).
3. **Роли.** Диспетчер и сотрудник — одна форма; роль назначает администратор при подтверждении, при регистрации не выбирается.
4. **Утечка данных.** Ответ восстановления одинаков для известной и неизвестной почты; экран «Письмо отправлено» показывается всегда.
5. **«Открыть пример письма»** — только в режиме разработки с моком (ведёт на `/reset?token=demo`); в релизной сборке кнопки нет.
6. **Таймер повторной отправки** считается по `retryAfterSec` из ответа и от времени на клиенте; живёт при перезагрузке экрана
   (метка времени в `sessionStorage`), чтобы обновление страницы не позволяло обойти ограничение на клиенте (сервер ограничивает отдельно).
7. **Адаптив.** Макеты 1440; ниже 900 px левая панель скрывается, остаётся карточка с логотипом сверху; карточка
   `max-width: 460`, поля на всю ширину. Минимальная ширина — 360.
8. **Язык и стиль.** Тексты по-русски, по макету; правила полей, ссылок и переключателей — из `konkrit-ui-preferences`.

## Безопасность
- Пароль не логируется и не попадает в URL; токен восстановления берётся из `?token=`, сразу убирается из адресной строки
  (`router.replace`) и не передаётся на сторонние ресурсы (`Referrer-Policy: no-referrer`).
- Ограничение попыток и блокировки — на бэкенде; клиент показывает `rate_limited` с временем ожидания.
- Проверки на клиенте — удобство; решающие проверки на сервере.
- Путь возврата после входа (`?next=`) принимается только внутренний (начинается с одного `/`).

## Существующие данные
В базе ничего не меняется: изменение добавляет клиент и контракт. Данные сотрудников и заявок на доступ создаст бэкенд
отдельным изменением; контракт обратно совместим (только новые пути).
