# Дельта: вход сотрудника

Макеты: «Авторизация: вход», «Авторизация: ждёт подтверждения» (1440).

## ADDED Requirements

### Requirement: Форма входа
Экран `/login` MUST показывать заголовок «Вход», подпись «Войдите в кабинет, чтобы работать с заявками и задачами.»,
поля «Электронная почта» и «Пароль» (с кнопкой «Показать пароль» / «Скрыть пароль», зона нажатия не менее 44),
чекбокс «Запомнить меня» (по умолчанию включён), ссылку «Забыли пароль?», кнопку «Войти» и строку
«Нет аккаунта? Зарегистрироваться».

#### Scenario: Успешный вход
- **WHEN** введены верные почта и пароль и нажата «Войти»
- **THEN** кнопка блокируется на время запроса, сессия создаётся, открывается кабинет (или путь из `?next=`, если он внутренний)

#### Scenario: Пустые поля
- **WHEN** нажата «Войти» с пустой почтой или паролем
- **THEN** запрос не уходит; под полем «Введите почту» или «Введите пароль», фокус на первом поле с ошибкой

#### Scenario: Неверная почта по формату
- **WHEN** почта не похожа на адрес
- **THEN** под полем «Проверьте адрес почты»

#### Scenario: Неверные данные
- **WHEN** сервер ответил `invalid_credentials`
- **THEN** над кнопкой «Неверная почта или пароль» (без указания, что именно неверно); пароль не очищается, введённая почта остаётся

#### Scenario: Слишком много попыток
- **WHEN** сервер ответил `rate_limited`
- **THEN** «Слишком много попыток. Повторите через [N] мин»; кнопка недоступна, пока время не вышло

#### Scenario: Нет сети
- **WHEN** запрос не дошёл
- **THEN** «Нет соединения. Проверьте интернет и повторите», форма сохраняет введённое

#### Scenario: Двойное нажатие
- **WHEN** «Войти» нажата дважды подряд или нажат Enter во время запроса
- **THEN** уходит один запрос

#### Scenario: Запомнить меня
- **WHEN** чекбокс снят
- **THEN** сессия не переживает закрытие браузера

### Requirement: Состояния учётной записи
Экран MUST различать статус записи, который вернул вход.

#### Scenario: Ждёт подтверждения
- **WHEN** сервер ответил `pending_approval`
- **THEN** открывается `/pending`

#### Scenario: Доступ отклонён или закрыт
- **WHEN** сервер ответил `rejected` или `blocked`
- **THEN** над кнопкой «Доступ не открыт. Обратитесь к администратору УК» (для `blocked` — «Доступ закрыт. Обратитесь к администратору УК»)

### Requirement: Экран «Ждём подтверждения»
Экран `/pending` MUST показывать янтарную иконку часов, заголовок «Ждём подтверждения», текст «Заявка на доступ отправлена
администратору «[УК]». Когда он откроет доступ, мы пришлём письмо на [почта].», кнопку «Вернуться ко входу» и строку
«Долго нет ответа? Напишите администратору: [email администратора].» (ссылка `mailto:`).

#### Scenario: После регистрации
- **WHEN** регистрация прошла
- **THEN** открыт `/pending` с названием УК, почтой и адресом администратора из ответа

#### Scenario: После неудачного входа
- **WHEN** открыт из входа с `pending_approval`
- **THEN** показаны те же данные из ответа входа

#### Scenario: Прямой заход или обновление
- **WHEN** страница открыта без данных (адрес набран вручную, данные потеряны)
- **THEN** показывается «Ждём подтверждения» без названия УК и почты, с кнопкой «Вернуться ко входу»

#### Scenario: Вернуться
- **WHEN** нажата «Вернуться ко входу»
- **THEN** открыт `/login`

### Requirement: Выход и защита кабинета
Маршруты кабинета MUST быть доступны только с сессией.

#### Scenario: Без сессии
- **WHEN** открыт `/` без сессии
- **THEN** открыт `/login?next=/`

#### Scenario: Вошедший открывает вход
- **WHEN** сессия есть и открыт `/login`
- **THEN** открыт кабинет

#### Scenario: Чужой путь возврата
- **WHEN** `next` содержит внешний адрес (`//evil.example`, `https://…`)
- **THEN** он игнорируется, открыт кабинет

#### Scenario: Сессия истекла
- **WHEN** сервер ответил отказом по токену и обновить его не удалось
- **THEN** сессия сбрасывается и открыт вход
