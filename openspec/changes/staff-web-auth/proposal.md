# Веб-интерфейс сотрудников УК: авторизация

## Зачем
У диспетчера и сотрудника УК пока нет веб-кабинета. Первым шагом нужен вход в него: вход, регистрация с подтверждением
доступа администратором, восстановление пароля. Без этого нельзя строить CRM-экраны (заявки, задачи, чаты, аналитика).

## Что меняется
- Новое веб-приложение `web/` на Vue 3 (Vite, TypeScript, vue-router, Pinia, Vitest).
- Шесть экранов по макетам «Авторизация» (1440): вход, регистрация, ждёт подтверждения, восстановление пароля,
  письмо отправлено, новый пароль.
- Общий каркас экрана авторизации: слева коралловая панель с описанием, справа белая карточка.
- Защита маршрутов: без сессии открывается вход; после входа — заглушка кабинета (сам кабинет — отдельное изменение).
- Контракт `api/openapi.yaml` дополняется эндпоинтами авторизации сотрудников; до готовности бэкенда веб работает на моке.

## Вне объёма
- Экраны CRM (заявки, задачи, акты, чаты, аналитика) и экран администратора УК, который подтверждает доступ.
- Бэкенд на Go и отправка писем (здесь только контракт и мок).
- Вход жителей: он в мобильном приложении.
- Двухфакторная аутентификация, вход через внешние сервисы.

## Влияние
- Новые файлы: `web/**`, `api/openapi.yaml` (добавление путей `/staff/auth/*`).
- Существующие данные: изменение не создаёт и не меняет данных в базе; миграций нет. Таблицы сотрудников и заявок на доступ
  появятся с бэкендом отдельным изменением.
