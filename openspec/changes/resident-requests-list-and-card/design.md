# Дизайн-решения

## Навигация

```
src/app/
  _layout.tsx                  корневой стек (как сейчас)
  (tabs)/_layout.tsx           нижняя навигация, 5 вкладок
  (tabs)/home.tsx              «Новости» (прежняя главная-заглушка, путь /home сохраняется)
  (tabs)/requests.tsx          «Заявки»: список
  (tabs)/services.tsx          «Услуги» — заглушка
  (tabs)/chat.tsx              «Чат» — заглушка
  (tabs)/profile.tsx           «Профиль» — заглушка с кнопкой «Выйти»
  requests/[id].tsx            карточка заявки (поверх вкладок, без нижней панели)
  requests/new.tsx, sent.tsx, failed.tsx   как сейчас
```

Группа `(tabs)` не попадает в адрес, поэтому `router.dismissTo('/home')` и `/requests/new` продолжают работать.
Вкладка «Заявки» — `/requests`. Нижняя панель: высота 72, белая, верхняя граница `#E6E7E8`, активная вкладка
`#A82E2E` жирная, остальные `#666A70`, зона нажатия не меньше 44, подписи 11/600, иконки макета.

## Контракт и типы

Новые типы: `RequestStatus` (`new | in_progress | waiting | completed | cancelled`), `RequestSummary`
(`id, number, title, categoryName, status, executor?: Person`), `RequestDetails` (+ `createdAt`, `address`, `curator?`),
`Person` (`name, position`), `ChatMessage` (`id, author: { role, name? }, mine, text?, attachment?, createdAt, state`),
`HistoryEvent` (`id, at, text`), `RequestFile` (`id, name, kind, url, size?`).

`ApiClient`:

- `listRequests({ status?, cursor? })` → `{ items: RequestSummary[], nextCursor: string | null }` (по 20)
- `getRequest(id)` → `RequestDetails`
- `listMessages(id)` → `ChatMessage[]`
- `sendMessage(id, { clientMessageId, text?, attachmentIds? })` → `ChatMessage` (повтор с тем же `clientMessageId` возвращает то же сообщение)
- `listHistory(id)` → `HistoryEvent[]`, `listFiles(id)` → `RequestFile[]`

Фильтр «В работе» запрашивает `status=in_progress,waiting`, «Завершены» — `completed,cancelled`, «Новые» — `new`, «Все» — без статуса.

Мок: 5 демо-заявок из макета, новые заявки из формы добавляются в начало; сообщения хранятся по заявке, ответ исполнителя
не имитируется (только заранее заготовленная переписка).

## Список

- `FlatList` с вытягиванием обновления и дозагрузкой по концу списка; один список на весь экран (прокрутка экрана и есть список).
- Состояния: загрузка («Загружаем заявки…»), пусто («Заявок пока нет» и кнопка «Создать заявку»), пусто в фильтре
  («В этом разделе заявок нет»), ошибка («Не удалось загрузить заявки» и «Повторить»).
- Кнопка «Новая заявка» плавает справа над нижней панелью (отступ 88 от низа), не перекрывает последнюю карточку (нижний
  отступ списка под неё).
- Карточка: категория 13/700 `#A82E2E`, плашка статуса, заголовок 15/600, «Исполнитель: …» 12/500 `#666A70`.

Цвета плашек: Новая `#E3EEFF`/`#1F4E9E`, В работе `#FFF1D6`/`#7A4B00`, Завершена `#DDF3E4`/`#1E6B3A`,
Ожидание и Отменена `#E6E7E8`/`#666A70`. Плашка статуса — один компонент `StatusBadge` на список, карточку и итог заявки (S9).

## Карточка

- Шапка: «Заявка № N» и «Назад». Верхний блок (создана, статус, заголовок, шкала из четырёх сегментов) и блок
  куратора и исполнителя закреплены, ниже вкладки «Чат / История / Файлы» (переключатель как на экране входа) и содержимое вкладки.
- Шкала: сегменты «Новая», «В работе», «Ожидание», «Завершена»; закрашены до текущего включительно.
  «Отменена» — шкала серая, плашка «Отменена».
- Заявки без куратора или исполнителя показывают «Не назначен».

## Чат

- Сообщения: чужие слева на белом, свои справа на коралловом; подпись автора («Исполнитель», «Куратор», «Диспетчер», «Вы»).
  Вложение-фото — картинка 160×96 с подписью автора; документ и видео — строка с иконкой и именем.
- Поле «Сообщение» (до 1000 символов), скрепка (лист «Добавить вложение» из формы заявки, те же лимиты и тексты) и «Отправить».
- Отправка с оптимистичным показом: сообщение появляется сразу с пометкой «Отправляется…»; при ошибке — «Не отправлено · Повторить».
  Каждое сообщение имеет `clientMessageId` (повтор не создаёт дубль).
- Файл отправляется после загрузки: сначала `uploadAttachment`, затем `sendMessage` с идентификатором.
- Опрос `listMessages` раз в 5 секунд, пока экран открыт и вкладка «Чат» активна; новые сообщения прокручивают список вниз,
  если житель был внизу.
- Клавиатура: поле ввода поднимается над клавиатурой (`KeyboardAvoidingView`), список остаётся доступным.

## Связки с прежним

- S9 «Открыть заявку» → `requests/[id]` с идентификатором созданной заявки.
- Заглушка `requests/details` и её экран удаляются.
- Карточка «Черновик заявки» в списке читает `useRequestDraft`: показывается, если форма «грязная», нажатие открывает `requests/new`.
- «Выйти» переезжает с главной-заглушки в «Профиль».

## Тестирование

Юнит: сопоставление фильтров и статусов, шкала статусов, склейка страниц списка, оптимистичные сообщения и повтор.
Компонентные: вкладки, список во всех состояниях, карточка, чат (отправка, ошибка, вложение, опрос на таймерах), черновик в списке.
